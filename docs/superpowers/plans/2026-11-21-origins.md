# Origins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `/origins/`, a page that draws the converging paths of SNUG's members as a braid computed from event records.

**Architecture:** Zola merges two data sources in the template (`content/events/` for the spine, `data/moments.toml` for personal history and join records) into a JSON blob. A TypeScript engine, bundled by esbuild from nixpkgs, computes abstract `(t, lane)` coordinates once and feeds two projections. The bundle is committed to `static/js/braid.js` with a freshness check, so Netlify needs no node.

**Tech Stack:** Zola 0.23.6, Tera, TypeScript via esbuild 0.27.2, `node:test` on nodejs 24.21.0, Python 3 + jsonschema for data validation, Nix flake for build and checks.

**Spec:** `docs/superpowers/specs/2026-11-21-origins-design.md`

## Global Constraints

- **Stage new files before any `nix` command.** Flakes see only git-tracked files; an untracked file is invisible to the build and to the formatting check.
- **Anything templates must read goes under `[extra]`** in front matter. Top-level keys build without error and are undefined in Tera.
- **`json_encode` must be followed by `| safe`** inside `<script>` blocks, or `JSON.parse` fails on `&quot;`.
- **No npm.** No `package.json`, no `package-lock.json`, no `node_modules`. esbuild and nodejs come from nixpkgs through the flake.
- **Both themes.** Every colour works in light and dark, following #97.
- **Commit trailer:** every commit ends with `Assisted-by: Claude Code (claude-opus-5)`. Plain engineer voice, no em dashes, no co-author trailers.
- **treefmt does not cover** templates, SCSS, TypeScript or Python. Do not add them.
- `content/about/` slugs are Zola-slugified: `daniel.baker.md` → `daniel-baker`.

## Review Focus

1. **A single moment** — rank spacing computes `index / (count - 1)`, which divides by zero when there is exactly one moment, producing `NaN` coordinates and an invisible braid. Pinned in Task 4.
1. **A person whose only moment sits in someone else's lane** — Rok's single moment is shared with Daniel and placed in Daniel's lane. A thread with no own-lane points must still render as a curve from its own lane, not a zero-length path. Pinned in Task 4.
1. **Guest with empty `image_url`** — the schema permits it. The renderer must emit an initial-letter fallback, never an `<img src="">`, which browsers resolve against the page URL and re-request. Pinned in Task 7.
1. **Future-dated events** — `content/events/` already holds events past today (2026-12-05). They stretch the `t` range and must not inflate trunk thickness beyond the people who have actually joined. Pinned in Task 4.
1. **`localStorage` unavailable** — private browsing throws on access. The existing theme switcher wraps every access in `try/catch`; the projection toggle must too, or boot dies and the page shows only the fallback list. Pinned in Task 8.

**Interfaces:**

- Consumes: `parseFuzzyDate` from Task 3.

- Produces:

  - `parseData(raw: unknown): { people: ReadonlyMap<string, Person>; moments: readonly Moment[] }` in `parse.ts`. Turns the `#origins-data` JSON, where `date` is a raw string, into typed records with `FuzzyDate`. Throws `TypeError` naming the offending field on malformed input. Pre-flight ruling: no task owned this, and without it Task 7's `main.ts` would deserialize the page's only data input untested.
  - `assignLanes(moments: readonly Moment[]): Map<string, number>`
  - `buildBraid(moments: readonly Moment[], people: ReadonlyMap<string, Person>): Braid`

- `PlacedMoment` is `{ moment: Moment; t: number; lane: number }`, `t` the rank position in `[0,1]`. There is no `tStart`/`tEnd`: under rank spacing a fuzzy date does not occupy a span of the axis, so imprecision is carried by `moment.date.precision` and rendered in the node, not in its extent.

- `ThreadSegment` is `{ points: readonly PlacedMoment[]; kind: "approach" | "excursion" }`. A thread is drawn as its segments; the gaps between them are where it is travelling inside the trunk and not drawn separately.

- `Thread` is `{ person: Person; lane: number; segments: readonly ThreadSegment[]; joinsTrunkAt: string | null }`.

- `Excursion` is `{ moment: PlacedMoment; lane: number; from: PlacedMoment; to: PlacedMoment | null; leaves: readonly string[]; recruits: readonly string[] }`. `from` is the trunk moment immediately before it and `to` the one immediately after, or `null` when none exists yet. `leaves` are people already in the trunk; `recruits` are people joining here.

- `TrunkSegment` is `{ from: PlacedMoment; to: PlacedMoment; joined: number; away: number }`. Thickness is a function of `joined - away`.

- `Braid` is `{ moments: readonly PlacedMoment[]; threads: readonly Thread[]; trunk: readonly TrunkSegment[]; excursions: readonly Excursion[] }`.
